# Contributing

Thanks for your interest in contributing to **[Project Name]**. This document describes the contribution process; replace the placeholders to fit the project before accepting contributions.

## Before You Start

- Check existing issues and pull requests to avoid duplicate work.
- For a significant change, open a discussion or issue first and wait for maintainer direction.
- Do not submit client information, confidential company material, credentials, API keys, passwords, or other secrets.
- Confirm that the project owner has approved the contribution and that you have the right to submit it.

## Development Setup

1. Install the prerequisites listed in the project README.
2. Follow the README installation and configuration instructions.
3. Keep secrets in local environment variables or an approved secret manager; never commit them.

## Change Guidelines

- Keep changes focused and explain the reason for them.
- Follow the existing style and architecture.
- Add or update tests and documentation when behavior changes.
- Run the relevant tests, formatter, and linter before opening a pull request.

## Pull Requests

1. Create a branch with a descriptive name.
2. Make and test your changes.
3. Open a pull request using the provided template.
4. Explain the problem, solution, and verification steps; link related issues where appropriate.
5. Address review feedback. Changes are not approved or merged until a maintainer says so.

## Questions

Use the repository’s issue/discussion channels for non-sensitive questions. For security concerns, follow [SECURITY.md](SECURITY.md), not a public issue.
